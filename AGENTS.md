# AGENTS.md

- AI model IDs (Gemini, Groq, OpenAI images) and the default reasoning effort for edge functions live only in `supabase/functions/_shared/models.ts`; import from there instead of hard-coding model strings, so a model upgrade is a one-line change.
- Calls on thinking Gemini models send `reasoning_effort` (low by default for live-session latency) and no `max_tokens`, because thinking tokens count against the output cap and can truncate replies.
- Live question detection defaults to the pause-based AI scanner (`scan-transcript-questions` + `useLlmQuestionScanner`), which returns the question and answer data in one call; regex detection only surfaces candidates while AI scans are failing, so detection quality doesn't depend on brittle word rules.
- The question scanner calls Groq directly (JSON mode, short timeout) and falls back to the gateway's flash-lite model without reasoning, because scan latency decides how fast questions reach On Deck; a missing or failing Groq key must never stop detection.
- Timed auto questions are misconception-first: when the interval is reached, `generate-interval-question` is called with `misconception_required` during a grace window (`src/lib/misconceptionCadence.ts`) and only sends a question whose wrong choices each map to a named misconception; after the window it accepts the best grounded question, so pacing holds without the instructor doing anything. Auto questions bypass On Deck and carry their `misconception` metadata into `question_content`.
- Live question pictures are stored on Cloudinary through `supabase/functions/_shared/questionImageStore.ts` (On Deck pre-generations use a fixed public ID so Send Now can reuse them), because hand-signed R2 uploads kept failing; background picture jobs must be wrapped in `EdgeRuntime.waitUntil` or they are cut off when the response returns.
- Live question pictures illustrate the correct answer and are shown only after a participant answers (feedback card, recap, dashboard history), never on the open question, so they cannot give the answer away and have the whole answer window to finish generating.
- Account-linked participants retain read access to their session questions after the session ends through the existing current-user membership helper; keep this check independent of session activity so saved answer history remains reviewable without recursive RLS.
- Live participant delivery polls every three seconds independently of image readiness, recovers newer questions in order, and queues arrivals until current feedback is dismissed; this prevents lost questions and preserves active answers during grading.
